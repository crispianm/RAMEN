# scripts/s3: S3 (noise ladder + post-hoc filter bed) provenance helpers
These files reproduce the *released* S3 numbers (tab:noise and the supp_filters indices) from the per-file results; they are not part of the training or scoring code. Commit under which the S3 jobs ran ("I3"): `1a67278bc331be59404979f4ab2e3bcd1ca69655`.
- `s3_ladder_pairs.json`: the seed pairs for the ladder gain G (numerator = RAMEN c3 n46/47/48, denominator = the seed-matched Metric-VDA-S FT; stages none / +agf0.2t0.06). Input of `s3_ladder_G.py`.
- `s3_ladder_G.py`: computes G = RAMEN / FT per seed from the ladder per-clip files (outside the generator): `python3 -I s3_ladder_G.py --dir <jobs/L_NOISE/per_clip> --pairs s3_ladder_pairs.json --datasets bonn,kitti --rungs llb3x1,llb3x2,llb3x4,llb3x8,llb3x16 --split dev --out <dir> --noise-levels <noise_levels.json>`.
- `s3_vars_ladder.sh` (sha256 b184040c...) and `s3_vars_filters.sh` (sha256 362a8e42...): the two variable files exactly as the S3 jobs ran them (byte-identical to the copies recorded in the jobs' `scripts.sha256`: the ladder job L_NOISE used the first, the filter job F_FILTERS the second). The filters file still carries an unfilled `S3_WANT` placeholder, which the filter track does not use.
- `ft_filter_cells.py`, `ft_frontier.py`: FT version of the supp_filters index tool (cell table from the seven FT n46 filter variants, then the six indices re-pinned to FT n46). `ft_frontier.py` is the earlier `frontier.py` with only the input pin, the reference row and the plot labels changed. `python -I ft_filter_cells.py <F_FILTERS model dir> <out>` then `python -I ft_frontier.py <out>/ft_cells.csv <sha256 of that file> <out>`.
Note: `configs/paper_results.yaml` is left byte-identical to the S2 / figure-job config. Its `tab:noise` `seeds.degradation` string still mentions the dropped `llb3kappa1` rung ("llb3kappa1: kappa 1.0"); that rung is not part of the released `tab:noise` (cells are llb3x1..x16 and the static ones only).
