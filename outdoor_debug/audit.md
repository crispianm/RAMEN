Scope: PLAN Priority 0 (critical checks) plus the Phase 1-11 audits done so far. Models: C3 seed 45 (headline), RAMEN n46, FT n46, with released Metric-VDA-S as the reference. DEV/train data only; no TEST split opened; no training (the Priority-1 overfit tests are reported separately). Evidence per area is in parts/<id>/FINDINGS.md (A_model, B1_datasets, B2_transforms_masks, C1_losses, C2_config_train, D_baseline, E_gradients). ## Verdict in one paragraph
No code bug has been found in the metric head, the depth/disparity conversions, the unit decoding, the resize/crop/mask pipeline, the optimiser or the loss implementation. What the audit did find is a shared-recipe property that fits the symptom: **real far-field and sky depth is never supervised, and the synthetic sources that do supervise it do so weakly (VDA-only, 1/d^2-decayed) or wrongly (TartanAir's finite saturated sky is mostly labelled valid)**. All our models place sky and far geometry 2-4x nearer than the release (level shift, no saturation), and RAMEN matches FT, so this is the shared recipe, not RAMEN's architecture. The cause has NOT yet been isolated: what is established is where the supervision is missing, not that adding it fixes the symptom (that is Priority 2).

## Ranking for Priority 2 (hypotheses, NOT confirmed causes; nothing below has been trained)
1. Missing metric supervision of far field and sky (M-01, M-02, M-03, M-05): test the existing opt-in sky hinge (one factor) and a metric far/log-depth term; test TartanAir sky-rule fix as a separate factor.
2. KITTI/NYU repetition and KITTI's tiny gradient share (M-07): rebalance (Exp M/J).
3. Head drift at full lr (M-09): head_lr_mult 0.1.
Plan stop condition applies: no ablation or Isambard job until the user and the Auditor clear Phase 12+.
