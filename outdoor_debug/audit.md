# Outdoor metric depth audit: Priority 0 (consolidated by the lead, 2026-10-16)
Scope: PLAN Priority 0 (critical checks) plus the Phase 1-11 audits done so far. Models: C3 seed 45 (headline), RAMEN n46, FT n46, with released Metric-VDA-S as the reference. DEV/train data only; no TEST split opened; no training (the Priority-1 overfit tests are reported separately). Evidence per area is in parts/<id>/FINDINGS.md (A_model, B1_datasets, B2_transforms_masks, C1_losses, C2_config_train, D_baseline, E_gradients). Visuals: /mnt/DATA/DegradedDepth/claude_outputs/scratch/outdoor_debug_20261016/ (index in VISUALS_INDEX.md). The two figures the user pointed at are in evidence_user_pointed/ there.

## Verdict in one paragraph
No code bug has been found in the metric head, the depth/disparity conversions, the unit decoding, the resize/crop/mask pipeline, the optimiser or the loss implementation. What the audit did find is a shared-recipe property that fits the symptom: **real far-field and sky depth is never supervised, and the synthetic sources that do supervise it do so weakly (VDA-only, 1/d^2-decayed) or wrongly (TartanAir's finite saturated sky is mostly labelled valid)**. All our models place sky and far geometry 2-4x nearer than the release (level shift, no saturation), and RAMEN matches FT, so this is the shared recipe, not RAMEN's architecture. The cause has NOT yet been isolated: what is established is where the supervision is missing, not that adding it fixes the symptom (that is Priority 2).
