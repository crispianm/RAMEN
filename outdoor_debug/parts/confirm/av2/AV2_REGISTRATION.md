- Pairing and ego-pose transform (VERIFIED from the dataloader source quoted by the docs fetch): the official API takes `city_SE3_egovehicle` at EXACTLY the lidar timestamp and at EXACTLY the camera timestamp (RuntimeError if absent) and chains ego(t_lidar) -> city -> ego(t_cam) -> camera via `egovehicle_SE3_sensor`. - Pairing rule: each scored camera frame is paired with the nearest-timestamp LiDAR sweep (ties to the earlier); if |dt| > 50 ms (half a sweep period) the frame is DROPPED and the count reported. ## Sky mask (frozen, shared by both arms; per CONFIRM_PROPOSAL section 3 and Auditor O35 Q2)
Two segmenters (SegFormer ADE20K sky; Mask2Former/OneFormer Cityscapes sky = trainId 10), class ids asserted by name from id2label; both checkpoint shas and licences recorded here at pinning (UNSET now). ONE mask file `sky_masks.npz` keyed by frame id `<log>:<cam_ts>` with TWO layers at native 2048x1550:
- `certain`: both models sky with prob >= 0.9, eroded 8 px from non-sky (scaled to native), no projected LiDAR return within 5 px, above the horizon row if calibration gives it. Used ONLY for the PRIMARY.
- `any`: sky by EITHER segmenter at argmax, no threshold/erosion. Used ONLY to exclude pixels from the far-range guard. (Needed because `certain` is disjoint from LiDAR pixels by construction, so it could not remove false-sky LiDAR pixels from the guard.)
`certain` must be a subset of `any` (asserted by the loader). Mask panel (12 frames by fixed stride, committed BEFORE any prediction), the two forced-fail mask checks, IoU threshold 0.85 and dropped counts: as CONFIRM_PROPOSAL section 3 / O35 Q2. ## Metrics (exact; scorer `av2_scorer.py`)
Single seed 50 (data.seed 50); control = TS2 at seed 50, treatment = TS2+H300 at seed 50; same start c3_n46 step12000 (per the confirm proposal for the seed-50 start), same frames, same mask file.
- PRIMARY (prediction-only, sky pixels): per scored frame, median PREDICTED depth over `certain`-sky pixels at the model grid (mask nearest-resized; frames with < 2000 such px dropped, count reported); P = median over kept frames (frame-balanced). d = ln(P_H300 / P_TS2). Descriptions (not decision): pooled sky median, frac of sky px > 200 m and > 300 m.
- DECISION (Auditor O36, single seed): CONFIRMED iff d >= ln 1.5 (= +0.4055) AND all guards pass. 0 < d < ln 1.5 = NOT CONFIRMED. d <= 0 = REFUTED. (A large d with a failed guard = NOT CONFIRMED.) Every summary of the result carries the single-seed disclosure: "SINGLE SEED (50): one paired difference cannot size seed noise; the A0/A0b screen pair showed 26% spread on a guard. Sign and magnitude only." Framing (O35): P measures what the hinge enforces by design; a pass is near built-in and is NOT an accuracy claim; the guards carry the information.
- GUARDS (AV2, per bin, unaligned, sky excluded): bins [0,20) [20,50) [50,80) [80,120) [120,200] m (half-open, last closed; 200.0 included, 200.001 excluded). On LiDAR-projected pixels only with the `any`-sky mask excluded. Per bin: pixel-pooled AbsRel = sum|p-g|/g / n and pooled median pred:gt (median of ratios), px, frames, logs; overall AbsRel (0,200]. Rule: H300 AbsRel <= 1.05 x same-seed TS2 AbsRel in EVERY bin. A bin with < 20,000 pooled px in either arm is reported UNEVALUABLE (neither pass nor fail; the verdict line names it) [the 20,000 threshold is a proposal; expected points per bin are [UNVERIFIED]: the farthest bins are expected to be sparse]. Also reported (no rule): frac of sky px > 200 m; px excluded as sky.
- Resolution rule (as A1): prediction bilinear (align_corners=False) to native 2048x1550 and sampled at the projected LiDAR pixels; GT is never resized (a non-native GT raises). No alignment, no clamping of predictions.
- Model input (mirrors ddad_scorer A2): bench_joint Resize lower_bound, ensure_multiple_of 14, INTER_CUBIC, short_side 378 (portrait 2048x1550 -> 504 x 378 by the same Resize; identical scale to the KITTI/VKITTI/DDAD rows), fp16 autocast, `out_hw` = model resolution with the shape assert; the primary uses the model-grid prediction, the guard uses the A1 upsample of the same forward pass.
- REFERENCE row (Auditor O36, description only, never in the decision): released Metric-VDA-S (`--spec metric_vda_s`, weights sha 3c28432b... as the DDAD A3 pin) through the same scorer, same frames/mask. Label: "released Metric-VDA-S at the registered 378 input, fp16; description only". Optional second description row: start checkpoint c3_n46 step12000 (no hinge) to show the continuation effect.
