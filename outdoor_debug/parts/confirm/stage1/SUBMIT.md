- **Seed mechanism (O39).** BOTH arms of a pair carry `data.seed` AND `training.resume_reseed` = 50/51/52 (the screen's A0b mechanism). With a resume the global RNG is restored from the checkpoint, so `resume_reseed` is what makes the post-resume noise draws differ across pairs; `data.seed` sets the sampler order (log `[data] ... seed=S*1000`). `resume_reseed` is not printed by train.py, so the stop check asserts it from the sha-verified config yaml (and the log's ` config :` line sha must equal that yaml's sha). Within a pair the seeds are identical => same data stream (not bitwise: bf16/atomics).
- **Base config (finding).** Each pair uses ITS OWN c3rep job config as base: `base/effective_ramen_nXX.yaml` = `train.load_config(configs/experiments/dn01_c3rep_20261009_c3_nXX.yaml)`, byte-equal to `session_briefs/c3_replication_20261009/provenance/dn01_c3rep_20261009/..c3_nXX.resolved.yaml` (sha256 n46 d286b62c.., n47 a3092bb1.., n48 fbe2dda7..; asserted in arms_stage1.py and the sbatch). n46/n47/n48 differ ONLY in data.seed and checkpoint_dir. The screen's base `effective_c3_seed45.yaml` differs from the n46 job config only in data.seed, checkpoint_dir, checkpoint_at_steps, resume_from (all overridden by the screen COMMON list), so the choice has no functional effect; using the own-job base just makes "continuation of the same recipe" literal.
