# T_trajectory: sky/far level and head gradients along training (diagnostics only, no training)
Checkpoints: released Metric-VDA-S (step 0, shared init) and ft_n46 / c3_n46 (= RAMEN n46) at steps 6000, 8000, 12000 (sha-verified; step12000 = the existing files). Config check (cfg_check.txt): the cfg embedded in every step6000/8000/12000 checkpoint of both runs equals effective_{ft,ramen}_n46.yaml and the step12000 cfg: 0 differing keys. DEV data only, fp16 autocast, one seed, clean cell unless stated. Scorer pipeline (bench_joint, as D_baseline). Files: trajectory.csv (long: model, step, dataset, quantity, value, n; dataset train_batches = mean over 20 train batches), run_traj_eval.py, grad_traj.py, assemble.py, make_plots.py, plots *.png (small); full-size plots, panels and batch cache in /mnt/DATA/DegradedDepth/claude_outputs/scratch/outdoor_debug_20261016/T_trajectory/ (panel_horse_f25.png, panel_kitti0023_f109_{b0s0,llb3}.png on a shared log colour scale; sky_vs_step, far_ratio_vs_step, grad_norm_vs_step).

## Answers
1. Compression is present already at step 6000, essentially full size: sky is 2-3x nearer than the release at 6000 in every dataset (KITTI per-frame sky median 458 m release vs 153 FT / 124 RAMEN; VKITTI 580 vs 276/266; horse sky band 630 vs 231/194). It does NOT grow after 6000; it partly relaxes toward the release between 6000 and 8000 and then plateaus (KITTI 153->198->202 FT; 124->190->160 RAMEN; VKITTI 276->344->325 FT; horse 231->218->228 FT, 194->203->200 RAMEN). So: the move away from the release happens in the first 6000 steps (not sampled earlier: the interval 0-6000 is unresolved), then flat/slightly recovering, never monotone, never back near the release (best step still 0.4-0.55x of it). Treat the 6000->12000 wiggles (10-25%) with care: one seed, and FT-vs-RAMEN ordering flips between datasets.
2. Far geometry, same picture. VKITTI pred:gt in the 80-655 m GT bin: release 0.995, FT 0.833/0.859/0.855, RAMEN 0.794/0.844/0.842 (steps 6000/8000/12000); near (<30 m) stays 1.09-1.12 throughout. Train batches: far-valid (80-655 m) pred/gt 0.85 release -> 0.63-0.70; near <10 m 1.42 -> 1.08-1.12; valid >=655 m pred/gt 0.04 -> 0.08-0.09 (improves slightly with steps); sky median 325 -> 208-252 m, share of sky pixels predicted <80 m 0.42 -> 0.30-0.31. Again step 6000 already shows the change; far pred/gt on train data is flat to slightly rising after.
3. Scored metrics: KITTI DEV AbsRel raw 0.130 release vs 0.169/0.141/0.148 FT and 0.141/0.135/0.148 RAMEN (aligned-scale 0.107 -> 0.083-0.088); VKITTI AbsRel by range: ours better than release at 10-80 m and >80 m (0.21-0.23 vs 0.277), worse at 0-10 m only at FT step 6000 (0.169 vs 0.143); ScanNet++ raw AbsRel 0.292 release -> 0.121-0.127 (all steps, already at 6000). Horse: sky band, tree line (226 -> 78-110 m) and ground band (6.8 -> 3.5-5.5 m) all shrink; the tree line and ground drop further between 6000 and 8000 (FT 109->78 m, RAMEN 100->80 m).
4. Gradients (20 train batches, seed 45, sources incl. ScanNet++ and NYU shard 000000 only, see caveats): head (output_conv) norms: VDA 1.37 (release) -> 1.00/0.98/1.08 FT, 1.09/1.08/1.10 RAMEN; SiLog 2.56 -> 2.20/1.95/1.93 FT, 1.96/1.96/2.08 RAMEN; SiLog/VDA ratio 2.4 -> 2.2-3.1, no trend (FT 3.1 at 6000 -> 2.6). The class shares of the full pred-map L1 gradient (near <10 m 0.97, mid 0.03, far 80-655 m 4e-4, sky 9e-4 to 1.1e-3) hardly change along the trajectory: release 0.9665 / 0.031 / 8.5e-4 / 2.3e-3 -> trained 0.971-0.974 / 0.025-0.028 / 4.0-4.7e-4 / 0.9-1.1e-3. I.e. the far/sky share halves between the release and step 6000 (since the model has already moved) and is then constant to 12000. Per-pixel sky L1 3.1e-8 -> 2.5-3.1e-8; sky-term head norm 0.33 -> 0.17-0.21. VDA-vs-SiLog head cosine ~0 (-0.01..0.13) at every step. Loss values fall slightly (full 1.17 -> 0.86 at 6000 -> 0.81-0.82 at 12000). Net: no gradient-share change along 6000->12000 that could explain a slow drift; the recipe's far/sky signal is small and stable from step 6000 on.
(The shares are far lower than E_gradients' because this mix includes ScanNet++/NYU, 0-10 m indoor with huge near-field gradients; do not compare absolute numbers with E.)

## Caveats
fp16 autocast eval, bf16 gradient forward; one seed (n46) so wiggles <~20% are not interpretable; no checkpoint between 0 and 6000, so whether the shift is abrupt or gradual early on is unknown; training metrics.jsonl curves were not analysed here. KITTI DEV pooled sky quantiles include colour-rule false positives (p10 ~20 m for all models, see D_baseline); medians of per-frame medians are less affected. NYU in the gradient part uses ONLY the complete shard train-000000 (the lead's later message says all shards now exist; not rerun, which would change the batch set and need ~45 min GPU); ScanNet++ = sem_test (if on disk) + subset140 as configured; the 20 batches therefore differ from E_gradients' (new sources, same seed) but are identical across the 7 checkpoints. RAMEN/C3 used activation checkpointing (numerically equal up to ~2e-5). The step-0 RAMEN-arch is represented by the released FT-arch model, as in E. Stored in trajectory.csv; GPU_LOCK truncated.
