# A_model findings (PLAN Phase 2 + Priority 0: metric-head max output, native depth vs disparity). CPU only, DEV data only.
Scripts (all in this folder, rerun with `~/.venvs/ramen/bin/python <script>`): `dump_cfg.py` (resolved configs -> resolved_cfgs.txt), `ckpt_keys.py` (-> ckpt_keys.out), `unit_tests.py` (-> unit_tests.out), `real_frames.py` (-> real_frames.out/.json; ~25 min CPU).
Upstream checkout used: /mnt/DATA/DegradedDepth/competition/Video-Depth-Anything @4f5ae23 (the one VDANet imports; no `metric_depth/` dir and no separate metric head file exists in it, only `metric=True` flag on the same class).

## Bottom line
No architecture/representation bug found that caps outdoor range. The metric head is `Conv-ReLU-Conv-ReLU` (and one more F.relu), output in METRES, unbounded above, no hard-coded or configurable max depth in the model. All three checkpoints load strictly. Trained models do NOT saturate (max outputs 230-540 m, <0.1% of pixels within 1% of their own max, none at the 0 floor) but they predict sky/far markedly lower than released Metric-VDA-S on the same frames, equally for RAMEN and FT. That points at the shared training signal (Phases 3-5), not the head.

## Path-by-path interpretation (train vs val vs bench vs infer), all depth-native
- train: model(rgb) -> (B,1,T,H,W) metres. VDA-loss path: `_vda_disp` -> pd = 1/clamp(pred, 0.1, 1e5), gd = 1/clamp_min(depth,1e-3) (0 off mask; sky target disparity 0 with sky_vda_zero_disparity); SiLog on clamp(pred, 0.1, 1e5) vs depth (log). One inversion only.
- val (train.evaluate): pred -> disparity 1/clamp_min(1e-3); per-video LSQ on disparity with GT<80 m; aligned depth clamp [1e-3, 80]; abs_rel_metric = unaligned clamp [1e-3, 80].
- bench_joint: windows 32/step 22, metric stitching identity (scale 1, shift 0), bilinear resize to scorer size, aligned fit on disparity, unaligned = clamp(pd, 1e-3, max_depth=80) vs GT in (0.1, 80).
- infer.py streaming: metric -> raw metres, relative -> rescale/raw.
- Note the ST/RAMEN model (SharedTemporalNet) only changes the model INPUT (gated restored frames, depth_input 'restored') and unfreezes the whole DPT head + motion modules; the output stage is the same module as FT's.
